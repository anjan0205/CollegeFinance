# Agent & Project Guidelines: VIIT College Budget & ERP Platform

This repository follows the **System Architecture Documentation** standard to maintain shared clarity and support mindful evolution.

## Architecture Documentation Requirements

1. **System Overview**: Every major module must define its purpose, stakeholders, and boundaries.
2. **Visual Mapping (C4 & Mermaid)**: Architecture diagrams must be maintained in `docs/architecture.md`.
3. **Component Catalog**: Document responsibilities, interfaces, dependencies, and design rationale for services, controllers, and layouts.
4. **Data Architecture & Workflows**: Detail state transition matrices (e.g., P2P Procurement, 2-Tier Master Approvals) and persistence mechanisms.
5. **Cross-Cutting Concerns**: Explicitly document security policies, RBAC roles, input validation, and audit trails.

See [.agents/rules/system-architecture-documentation.md](file:///.agents/rules/system-architecture-documentation.md) for full specifications.
